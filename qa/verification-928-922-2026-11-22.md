account block (`:137`) is outside the `@if (showStaffNav())` that removes the nav. `showStaffNav`
(`app.ts:131-134`) returns false when `mustChangePassword`. If anyone moved the account block under
`showStaffNav()`, or gated the aside on it, the three `not.toBeNull()` assertions would go red. I tried
to prove this by mutating `app.html:108` and running the spec; the environment's permission classifier
refused the edit, so the mutation was **not** executed. The working tree is unchanged (`git status`
clean apart from untracked `qa/` files). Caveat: `SESSION.permissions` is `[]`, so the `nav.nav`
null assertion may hold for the empty permission set alone and does not by itself prove the
forced-change branch; the account-block assertions are the load-bearing ones.
